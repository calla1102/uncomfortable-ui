# uncomfortable-ui

일부러 쓰기 불편하게 만든 UI 20가지를 직접 눌러 볼 수 있는 웹입니다. 버튼이 도망가고, 자판이 매번 섞이고, 로딩바가 99%에서 멈춥니다. 하나씩 깨면 점수가 쌓입니다.

https://uncomfortable-ui.netlify.app

평소에 당연하게 넣는 것들(누르면 바로 반응한다, 입력한 대로 보인다, 버튼이 제자리에 있다)을 하나씩 빼 보면 어떤지 궁금해서 만들었습니다.

뼈대는 AI 사이트 생성 도구(Manus)로 만들었고, 그 뒤에 챌린지를 더하고 고쳤습니다. 코드는 AI 코딩 도구와 같이 썼습니다.

## 실행

```bash
pnpm install
pnpm dev
```

타입 검사는 `pnpm check`입니다.

## 들어 있는 것

| 묶음 | 챌린지 |
| --- | --- |
| 입력의 고통 | 랜덤 키보드, 슬롯머신 생년월일, 길게 눌러야 입력됨, 물리 엔진 이메일 입력, 패스워드 참참참, 캡차의 역습 |
| 정밀도 테스트 | 도망가는 확인 버튼, 타이밍 버튼, 마찰력 제로 관성 스크롤, 무게 중심 UI, 풍선 버튼 |
| 심리적 압박 | 조건부 팝업, 느릿느릿 로딩바, AI 채팅 상담사의 오타 |
| 시각적 혼란 | 다크/라이트 모드 무작위 전환, 스크롤 방향 반전, 조건부 폰트 크기, 저해상도 모드 강제 |
| 피드백 왜곡 | 점점 느려지는 입력, 입력값 변형 |

## 어떻게 돌아가나

React 19, TypeScript, Vite, Tailwind CSS로 만들었습니다. 챌린지 하나가 컴포넌트 하나이고 `client/src/components/challenges/`에 있습니다.

챌린지 목록은 `client/src/data/challenges.ts`의 배열 하나에 있습니다. 첫 화면의 개수, 카드 목록, 맨 아래 점수판이 모두 이 배열을 읽습니다.

화면 위의 스트레스 지수와 점수는 React Context 하나(`StressContext.tsx`)로 관리합니다. 실패하면 지수가 오르고 가만히 있으면 조금씩 내려갑니다.

몇 가지는 라이브러리를 쓰지 않았습니다.

- 물리 엔진 이메일 입력: 글자가 떨어지고 쌓이고 쓰러지는 계산(`PhysicsEmail.tsx`)
- 랜덤 키보드: 섞인 자판으로 누른 자모를 한글 글자로 합치는 조합기(`RandomKeyboard.tsx`)
- 저해상도 약관: Canvas에 작게 그린 뒤 늘려서 픽셀이 깨져 보이게 함(`LowResTerms.tsx`)
- 효과음: 음원 파일 없이 Web Audio API로 합성(`useSadSound.ts`)

## 만들면서 걸린 것

- 챌린지 개수가 화면마다 달랐습니다. 첫 화면은 11, 목록은 20, 점수판은 19였습니다. 숫자를 세 군데에 따로 적어 두고 챌린지를 추가할 때 한 군데만 고쳤기 때문입니다. 목록을 배열 하나로 옮기고 세 곳이 그 길이를 읽게 했습니다.
- 카드에 적힌 점수와 실제로 주는 점수가 20개 중 17개에서 달랐습니다. 전부 깨면 6,000점이어야 하는데 8,200점이 나왔습니다. 카드에 적힌 값으로 맞췄습니다.

## 아직 안 한 것

- 터치 화면. 대부분 마우스 이벤트로만 만들어서 휴대폰에서는 깰 수 없는 챌린지가 많습니다.
- 좁은 화면. 폭을 340~360px로 고정한 챌린지 넷이 휴대폰 화면 밖으로 넘칩니다.
- 키보드만으로 쓰기. 클릭만 받는 `div`가 여러 곳에 있습니다.
- 테스트가 없습니다.
- 안 쓰는 파일 정리. `client/src/components/ui/`는 shadcn/ui에서 가져온 것이고 그중 네 개만 씁니다. `Map.tsx`, `client/src/const.ts`, `server/`도 쓰지 않습니다.
